On GitHub Copilot, load batcave skills by their bare names through the `skill` tool (`batcave-mode`, `tdd`, `architect`, not `batcave:batcave-mode`); the plugin's agents keep the prefix (`batcave:batcave-agent`, `batcave:comment-sicko`). Copilot lists only part of a large plugin's skills in its prompt; every batcave skill a workflow names still loads by that name. `.github/copilot-instructions.md` and `~/.copilot/copilot-instructions.md` count as user instructions. Resolve every Claude tool, model, path, and built-in skill a batcave skill names through `references/copilot-tools.md` in the `batcave-mode` skill directory. batcave ships no default Copilot models. A skill that dispatches on role models takes them from the user's saved batcave model choices. The plugin hook reads them from the Copilot model sheet, `${COPILOT_HOME:-~/.copilot}/batcave-models.md`, checks them, and adds them to the end of this block. Do not `view` the sheet. It sits outside the workspace, so reading it asks for path access. After `setup-batcave` writes the sheet in this session, use the values it just wrote.

Skills that dispatch on role models: `architect`, `arena`, `batcave-mode`, `how`, `interrogate`, `reflect`, `swarm`, `why`.
